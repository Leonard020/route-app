## 2. 백엔드 API (`/api/v1`)

된 것:

- Envelope 응답, CORS, `/health`
- 인증: signup / login / refresh
- 장소 검색·최근검색 삭제 (로그인 시)
- 현재 위치 → 가까운 장소
- 경로 추천·상세·refresh·reroute·feedback
- 길안내 start / tick / end
- 버스: 도시코드, 정류소·노선별 도착 (TAGO)
- 지하철: 노선, 도착, sync (서울시)
- 사용자 이동 설정 GET/PATCH (로그인)

한계:

- 경로 후보는 그래프가 아니라 **가장 가까운 버스/지하철 지점**을 잇는 방식
- ETA는 규칙 기반 (`HeuristicPredictor`), ML 꺼짐
- 실시간 실패 시 DB 캐시, DB 실패 시 카탈로그 폴백

## 3. 데이터베이스

초기: PostGIS, users, places, routes/steps, 버스·지하철 실시간, raw/sync 로그.

이번에 추가 (`06_demand.sql` / `backend/app/sql/demand.sql`):

| 테이블/컬럼 | 원천 |
|-------------|------|
| `bus_hourly_boardings` | 노선·정류장·시간대 승하차 (0~23시) |
| `station_transfer_flows` | 하차ID→승차ID, 시간대, 유형별 환승 수·평균시간(초) |
| `places.standard_bus_stop_id`, `ars_id` | 표준버스정류장ID, ARS |
| `subway_stations.card_stop_id` | 교통카드 정류장/역사 ID |
| `subway_station_transfers.avg_transfer_s` | 환승 평균초 캐시 |

경로 추천이 이 테이블을 조회합니다. **레코드 적재는 사용자가 줄 예정.**

## 5. 인프라

- Docker: `db`(PostGIS 5432), `api`(8000), `web`(5173), `gateway`(nginx 80)
- 브라우저는 `http://localhost` 한 주소로 웹+`/api`
- 로컬 개발: Vite가 `/api`를 `127.0.0.1:8000`으로 프록시. `VITE_API_BASE`는 비움
- 프론트 빌드가 있으면 FastAPI가 SPA도 서빙
